# Lot 120 — Critères d’alerte internships explicites

Le Dashboard expose un bilan des stages disponibles, de leurs formats et des offres dont les critères d’alerte sont remplis. Les formats peuvent se recouper. Chaque fiche et carte mobile indique si ses critères sont remplis, bloqués ou indisponibles. Les explications couvrent le périmètre off-cycle/long 2027, les Summer exclus, les informations contradictoires/inconnues, les réglages désactivés, le seuil de score et les exclusions, les offres inactives ou expirées, une source désactivée, une référence de collecte manquante et les conflits de source. La fraîcheur imparfaite est un avertissement distinct.

La politique programme est partagée avec le scanner et la livraison Telegram. Les critères et références sont recalculés à chaque observation, sans mise en cache des réglages, scores ou états actuels. Cet affichage n’est pas un historique d’envoi et ne déclenche aucun renvoi des anciennes offres : il faut aussi une nouvelle détection, une réouverture ou une modification significative lors d’une collecte validée. Les alertes et références ont une observation séparée des offres, comme les contrôles de santé existants.

Le lecteur commun des références extrait uniquement les champs de preuve nécessaires et ignore aussi les dates de completion de type invalide ou hors plage. Aucun changement de schéma, de politique stages, de sources activées, de notifications supplémentaires ou de sessions d’accès privées.

Validation finale : 296 tests Python radar/collecteurs/stages, 272 tests Python Dashboard et 30 tests JavaScript réussis (568 Python distincts). Ruff des fichiers concernés et mypy des trois modules de référence/couverture/critères réussis. Navigateur réel à 390 px : filtres année et préférences, explications stage éligible/inconnu/contradictoire, suivi privé et persistance, téléchargement calendrier avec échéance précise et action, retrait des dates de dépôt après candidature, exclusion des notes privées du calendrier, zéro erreur JavaScript et aucun débordement horizontal. Les essais de modification utilisent exclusivement une base synthétique.

Déploiement avec sauvegarde vérifiée et conservation contrôlée des identifiants, historiques, alertes envoyées, base et curseur Telegram. Image immuable dédiée, cinq services et HTTPS privé vérifiés. Les limites d’accès employeur restent explicites et aucun CAPTCHA n’est contourné.


Le contrôle en production a identifié une différence de rôle : le service Dashboard garde `ALERTS_ENABLED=false` et `TELEGRAM_CONTROL_ENABLED=false`, tandis que le radar a ses alertes actives. Le champ non secret `DASHBOARD_RADAR_ALERTS_ENABLED` transmet désormais l’état du radar pour la consultation des critères, sans activer de notifier dans le Dashboard. Le déploiement le lit dans le radar existant et le mémorise dans la configuration Dashboard ; l’audit compare l’affichage à l’état réel du radar. Les secrets Telegram restent absents. Le test de cette séparation vérifie l’affichage positif, sa désactivation et l’absence de modification de la configuration ou de la base.
